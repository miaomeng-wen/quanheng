# 《权衡》安全自评报告

## 1. 权限分级实现说明

系统所有业务动作统一经权限闸门（`server/gate.js`）分级，Agent 与前端均无绕过通道：

| 级别 | 执行策略 | 本系统覆盖操作 |
|---|---|---|
| 绿色 | 意图确认后自动执行 | 余额/流水查询、账单分析、理财产品与收益查询、订阅查询、风险测评、AA 平摊计算 |
| 黄色 | 展示操作详情，用户明确确认后执行 | 小额转账（日累计 ≤1000 元）、取消订阅、虚拟卡申请、卡片限额调整、取消计划 |
| 红色 | 多因子强验证后执行 | 大额转账（日累计 >1000 元）、理财申购与赎回、卡片挂失/解挂、备资计划创建 |

关键机制：

- **参数绑定**：授权请求生成时对规范化参数做摘要哈希，执行时重算比对；红队实测中在授权请求里夹带篡改金额被忽略，仅按卡面金额执行。
- **授权不可重放**：同一授权卡执行后失效，重复提交被拒（红队实测通过）。
- **执行时复检**：计划步骤等延迟执行在执行前重新校验授权、账户状态与余额。
- **验证码重试限制与熔断**：连续验证失败或注入尝试达阈值后，敏感操作锁定（BREAKER_LOCKED），纯查询保持可用（红队实测通过）。

## 2. 安全机制逐项自评

| 赛题要求 | 实现 | 证据 |
|---|---|---|
| 幻觉防护 | 回复中的金额、余额、持仓只能来自工具返回值并模板化拼装；测算结论附假设与“不构成税务建议”声明；LLM 仅输出受校验的意图 JSON，不产生业务数据 | 代码结构；红队越权用例 |
| 注入防御 | 输入护栏对绕过确认/验证、冒充系统、索取验证码等模式拦截并计数、记审计；未被护栏命中的注入语句也只能进入正常授权流，无法直达执行 | 红队 6 变体实测：4 个直接拦截，其余未产生任何资金动作 |
| 操作审计 | 全部关键操作写入追加式 JSONL 审计日志，SHA-256 哈希链串联，面板可查且提供完整性校验 | 红队审计链校验 valid=true |
| 异常熔断 | 验证失败、注入尝试触发熔断；锁定范围限于敏感操作 | 红队熔断用例 |
| 沙箱环境 | 全部业务运行于内置模拟银行（种子数据、模拟时钟），无真实资金、无外部银行接口；LLM 端点未配置时不发起任何外部请求 | 部署形态 |

## 3. 红队实测结论

2026-10-27 以真实 HTTP 服务执行 8 例攻击（脚本 `tests/redteam-run.js`，全文 `docs/redteam-2026-10-27.md`）：授权参数篡改、授权重放、审计链完整性、提示注入变体 ×6、连续错码熔断、越权查询他人余额、负数金额、超余额大额转账——**8/8 通过**。其中越权查询用例在首轮发现“问他人余额却返回本人数据”的答非所问问题，已修复为明确拒绝并复测通过。

## 4. 已知风险清单

1. **演示环境简化**：强验证使用固定演示验证码，未接真实短信/人脸/U 盾；单用户模型，未实现多用户隔离与登录体系。生产化需接入银行级身份与多因子服务。
2. **状态不持久**：演示部署为内存状态，服务重启后数据与审计重置；生产化需持久化存储与审计归档。
3. **意图理解覆盖**：以规则为主、LLM 兜底已启用（智谱 GLM-4-Flash 免费档）；免费档存在拥堵与限流可能，适配器设 5 秒超时并自动降级至规则解析，不影响可用性；两者都未覆盖的表达会礼貌拒绝并提示范围，不会误执行。
4. **税务参数时效**：单独计税政策执行至 2027-12-31，引擎已对政策到期情形给出提示；后续政策变化需更新 `data/tax-policy.json` 并重新核验。
5. **前端会话安全**：演示站点无登录态，任何持有链接者可操作同一演示账户（数据为虚构种子）；正式提交与答辩场景下可接受，对外传播时应注意。
6. **异常交易识别为规则版**：基于金额与陌生商户规则，未引入机器学习模型，存在漏报/误报空间。

## 5. 改进路线

- 接入真实多因子认证与用户体系；审计日志落盘并支持导出。
- LLM 兜底配置合规端点后扩大口语覆盖，并对意图结果做二次确认提示。
- 异常检测引入行为基线与模型评分；计划步骤支持失败重试与人工接管工单。
